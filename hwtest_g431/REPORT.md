## 2. 问题一：当前调用了哪些外设

**hwtest 固件实际使用：**

| 外设 | 引脚 | 用途 |
|---|---|---|
| GPIO（LED） | PC8~PC15 + PD2 | 8 个 LED，经 74HC573 锁存（低电平点亮） |
| GPIO（按键） | PB0/PB1/PB2/PA0 | B1~B4，上拉输入，UI 交互 |
| USART1/2/3 | PA9/PA10、PA2/PA3、PB10/PB11 | 调试输出三路同播 115200 |
| GPIO（LCD 控制） | PB9=nCS、PB8=RS、PB5=nWR、PA8=nRD | LCD 8080 并口控制线 |
| GPIO（LCD 数据） | PC0~PC15 全端口 | LCD 16 位数据总线（与 LED 复用，靠锁存隔离） |
| SysTick | - | 1ms 系统节拍 |
| DWT CYCCNT | - | 微秒级计时（所有性能测量） |

**注意**：PA8 在这块板上是 LCD_nRD 而不是蜂鸣器（4T 官方 HAL_06_LCD.ioc 证实）；常见资料里"蜂鸣器=PA8"的说法对 CT117E-M4 不成立。PC13 疑似背光控制线（已接 UI 的 B3 开关，待用户目视确认）。

**未使用**：ADC（电位器/光敏）、I2C（AT24C02 EEPROM）、SPI、USB、CAN、HSE/PLL（保持 16MHz HSI）。

## 5. 问题四：仿真 vs 实机对比 + 仿真器优化

### 5.1 优化前的问题（现状审计）

- `simulate_chip()` 是**空转循环**：`mcu.tick(cycles_per_ms)` 循环 duration 次不执行任何 EFW 代码、不建模任何框架语义，报告里的"总周期数"只是循环计数
- 芯片库**没有**用户手上的 STM32G431RBT6（只有 CBT6），G4 族还被映射成"F411 替代"
- 没有任何与实机数据的对照

### 5.2 优化内容（已落地）

1. `data/mcu/STM32G4/STM32G431RBT6.json` + index：新增目标芯片（含板级布局：LED/按键/LCD 总线/DAPLink）
2. `core.py`：MCUType 增加 STM32G431，取消 F411 替代映射
3. **`tools/simulator/efw_model.py`（新）**：以实机 DWT 实测值为锚点的 EFW 工作负载模型——
   所有操作成本以 CPU 周期存储（实测 ns@16MHz 换算），可按任意主频缩放；支持配置
   注册表深度/查找次数/PID 环/发布/队列/任务数，输出每 tick 周期数、CPU 利用率、余量
4. `efw.py simulate --workload efw|idle`：CLI 暴露新模型（默认保持旧行为兼容）

### 5.3 对比矩阵（同一套 EFW 逻辑）

| 维度 | 实机（CT117E-M4） | 主机原生构建（新增 `host_build.sh`） | 旧 simulate | 新校准模型 |
|---|---|---|---|---|
| 执行真实 EFW 代码 | ✅ | ✅（同一 tests.c） | ❌ 空转 | ❌（解析模型，诚实标注） |
| 逻辑等价 | 23/23 PASS | **21/23 PASS**（2 个时序项） | - | - |
| 时序确定性 | span=19µs | OS 抖动 span=470µs（非实时 OS） | 无 | 周期级估算 |
| lookup 耗时 | 15.7µs | 10ns（~1500×，3GHz vs 16MHz+闪存等待） | 无 | 按主频缩放 |
| LCD/外设 | 真实面板 0x9325 | 无头 stub | 无 | 无 |

主机对照的 2 个 FAIL（scheduler_basic 计数窗口、jitter span）均为 **OS 非实时调度所致，是预期差异**——恰好证明：**逻辑正确性可在主机回归，时序确定性必须上实机**。

## 7. 框架改进建议（累计）

1. 头文件使用 `bool` 未含 `<stdbool.h>`（严格 C99 编译失败）
2. 调度器 def 指针契约（栈局部定义 → 悬空指针 aliasing，建议按值拷贝或文档加粗）
3. 循迹权重方向约定文档矛盾（ch0=最左 vs 转向语义）
4. **[新]** 注册表 O(n) 查找在满载（32 条）时 136µs@16MHz——建议高频路径文档更显著地标注 handle 模式，或为注册表增加哈希/索引选项
5. **[新]** 模拟器建议继续演进：把 efw_model 与 codegen 的 graph 元数据打通（从 Graph 自动推导 workload）
6. **[v3 已实装]** 调度器无时钟源模式时间基准修复：`now_ms` 误用增量导致任务永久沉默（游戏实测暴露，改为累加虚拟绝对时间）
7. **[v3 已实装]** G4 备份域时钟使能：`RTCAPBEN = RCC_APB1ENR1 bit10`（按 F4 习惯写 bit14 无效）——最高分存档修复；G4 外设使能位必须逐个对照头文件
8. **[v3 已实装]** 新增 `core/pool.h` 固定块内存池（O(1) 分配释放，5 万次随机测试 0 违规）

## 9. v3 追加：80MHz 提速 + 边界压测（2026-09-12 深夜）

### 9.1 80MHz 时钟提速（已修复并实测）

| 主频 | efw_init | sensor 查找(3条) | PID 单次 | LCD 全屏清除 | 状态 |
|---|---|---|---|---|---|
| 16MHz HSI | 48µs | 15.7µs | 29.9µs | 91-105ms | ✅ 基线 |
| **80MHz PLL** | **11-12µs** | ~6µs(推算) | ~7µs(推算) | **21ms** | ✅ 稳定运行 |

80MHz 配置：HSI16/2×20/2（PLLREN=PLLCFGR bit24 必须置 1——G4 独有的输出使能位）。
时钟净化已加入固件：**Keil 烧录算法会把时钟留在 HSE 上且不复位 RCC**，固件启动时必须先把 HSI 拉起、切回 HSI 再上 PLL。

### 9.2 G4 vs F4 三大编码差异（本次踩坑全记录）

1. `RCC_CR`：HSION/HSIRDY 在 **bit8/bit10**（F1/F4 风格是 0/2）
2. `RCC_APB2ENR` 在 **0x60**（0x58 是 APB1ENR1）
3. `RCC_CFGR`：**SW=11 才是 PLL**（10 是保留值，写入被硬件静默忽略！）；SWS_HSI=01

### 9.3 边界压测结果

| 边界项 | 实测值 | 结论 |
|---|---|---|
| 注册表查找快速路径 | 3 条：15.7→9.3µs（同前缀注册表收益有限，32 条反而 136→184µs） | 首字符否决只对异前缀有效；根治=句柄模式或哈希 |
| 频率扫描 | 80MHz ✓；**120MHz 起失败：PLL 运行中 SW=HSI 写入被硬件拒绝（3 次 DSB 重试无效，CFGR=0xF 纹丝不动）** | 待查 RM0440 PLL→HSI 切换规则；变频需复位后进行 |
| 调度器饥饿 | 无阻塞=999/1000；1 个阻塞任务=333；2 个=**166** | 协作式调度的硬边界：一个 3ms 任务挤掉 2/3 的 1ms 任务 |
| 事件饱和 | 29 万次发布/秒（4 订阅者）@80MHz | 总线不丢事件 |
| 队列吞吐 | 28.9 万次往返/秒 @80MHz | - |
| UART 吞吐 | 86.9µs/字符（波特率限制）→ 1ms 预算只容 11 字符日志 | 高频日志必须走 DMA |
| 栈水位 | 2048B / 32KB | 含 LCD/测试最深调用 |

### 9.4 框架改进（已实装并回归）

1. `core/pool.h`（新增）：固定块内存池，O(1) 分配/释放，5 万次随机测试 0 违规
2. `core/registry.h`：`efw_name_eq` 快速路径（指针相等 + 首字符否决）
3. `core/diagnostic.h/.c`：诊断钩子 `efw_diag_set_hook()`——错误统一观察点
4. **`core/scheduler.h/.c`：任务定义按值拷贝**——根治栈局部定义悬空指针问题（实测验证）
5. host 构建修复：TAMP 寄存器访问加 HOST_BUILD 保护；主机回归 22/24（仅 2 个 OS 时序项）
6. **`core/scheduler.c`：无时钟源模式时间基准修复（框架缺陷，游戏实测暴露）**
   - 缺陷：未注入时间源时 `now_ms = elapsed_ms`（每次 tick 的增量），而任务 next_release
     按绝对时间种子化——首次 tick 追赶后（elapsed≈3000ms），now_ms 永远只有 1~3ms，
     lateness 恒为巨大负数 → **所有调度任务永久沉默**
   - 触发条件：不调用 `efw_scheduler_set_time_providers()` 的应用（街机正是如此）
   - 修复：无时钟源时 `g_last_tick_ms += elapsed_ms` 累加为虚拟绝对时间，now_ms 取累加值
   - 验证：街机三个任务（10ms 输入扫描/60ms LED/500ms 遥测）全部按周期复活
