# 01 产品与模型

## 一句话

EFW Studio 用**能一句话读懂的结构**描述嵌入式 C 应用，自动生成可运行、可观测的代码；业务逻辑仍写在你自己的 `.c` 文件里。同一个应用可以在**虚拟目标**（无硬件、时间可控）和**真机**上用同一套界面调试。

## 用户只需要理解五个词

| 词 | 含义 | 类比 |
| --- | --- | --- |
| **输入 / 输出** | 硬件的读与写。每个对应一个 C 函数（放在 `board/`） | 引脚、传感器、电机 |
| **信号** | 应用内共享的一个有名字、有类型的数据 | 全局变量，但可观测、可整定 |
| **数据流** | 每 N ms 按顺序执行的一列步骤 | 一个周期任务 + 它的内容 |
| **状态机** | 若干状态；每个状态决定哪些数据流运行；由事件、超时或信号条件切换 | 工作模式 |
| **事件 / 队列** | 事件：无数据的通知。队列：类型化的 FIFO，用于中断 → 主循环 | 消息池 |

没有节点图、端口、契约、Topic、发布订阅。用户不需要连线；引用关系用下拉框选择，界面自动画出全局关系图。

## 一个应用长什么样

```text
恒温控制
  输入   温度传感器 (float, °C)        输出  加热器 (float, 0..1)
  信号   temp_raw  temp  target(可整定)  duty
  数据流 heat  每 10ms
           1 读取   temp_raw ← 温度传感器
           2 低通   temp ← temp_raw   系数 0.2
           3 PID    duty ← target - temp   kp ki kd
           4 写入   加热器 ← duty
  状态机 mode:  空闲 ──启动事件──▶ 加热 ──超时 600s──▶ 空闲
                   加热 状态下运行 数据流 heat
```

## 工作流（界面顺序即学习顺序）

1. **总览**：一张自动生成的结构图 + “下一步”清单。
2. **数据流**：用句子编辑步骤，拖动排序。
3. **状态机**：状态图 + “当 … 时从 … 到 …”。
4. **通信**：信号、事件、队列的表格，显示容量和内存。
5. **代码**：缺哪个函数一键创建，Monaco 编辑。
6. **调试**：虚拟目标 / 串口 / TCP / 回放，实时曲线、任务时序、状态、整定。
7. **生成**：逐文件 Diff，安全写入。

## 目录约定（用户能记住的一条规则）

```text
my_app/
  efw.json        模型（可读、可 diff）
  board/          碰硬件的 C（输入读取、输出写入、串口）—— 你拥有
  src/            纯逻辑的 C（自定义步骤、状态钩子）—— 你拥有
  generated/      工具拥有，可随时重新生成
  .efw/           布局、调试记录、备份
```

`board/` 只在真机构建时编译；虚拟目标用模型里的仿真配置替代 `board/`，所以**同一套 `src/` 逻辑在电脑上就能跑**。

## 非目标

不做任意 C 反向成图；不做自由画布；不覆盖用户源码；不做编译/烧录工具链管理（用你已有的 IDE 或 CMake）。
