# 05 界面风格（给后续开发者与 AI）

目标：**简洁、美观、直观**。像一台好用的仪器，不像一个 IDE。

## 原则

1. **一屏一件事**：每个页面只回答一个问题（总览=现在什么样；数据流=每个周期做什么…）。
2. **读得懂句子**：步骤、转换都用中文句子呈现，标识符用等宽字体，不暴露节点/端口/连线。
3. **少即是多**：不用阴影堆叠、渐变、装饰图；层次靠留白、字号和一条细线。
4. **颜色有含义**：钴蓝=可操作/选中；绿黄红=只表示状态；其余全是石墨灰阶。
5. **不自行推导**：调度、内存、诊断一律显示 `project.analyze` 的结果。

## Token（`ui/styles/tokens.css` 是唯一来源，组件里禁止写死颜色）

| 类别 | 变量 | 说明 |
| --- | --- | --- |
| 底色 | `--bg` `--bg-side` `--bg-panel` `--bg-inset` | 应用 / 侧栏 / 面板 / 内嵌（图表、代码） |
| 线 | `--line` `--line-strong` | 分割线 / 控件边框 |
| 字 | `--fg` `--fg-dim` `--fg-faint` | 主 / 次 / 弱 |
| 强调 | `--accent` `--accent-bg` | 钴蓝 / 选中底 |
| 状态 | `--ok` `--warn` `--err` | 只用于状态点、徽标、诊断 |
| 曲线 | `--s1`–`--s5` | 只用于数据可视化（示波器曲线） |
| 尺寸 | `--r` (4px 圆角) `--gap` (8px 基数) | 间距只用 4/8/12/16/24 |
| 字体 | `--sans` `--mono` | 界面 / 标识符与数值 |

明暗主题由 `prefers-color-scheme` 切换 token，组件无感。

## 布局

```
┌────┬──────────────────────────────┐
│ 资 │ 顶栏 40px：项目名 · 命令 · 重新载入 · 撤销/重做 · 运行 │
│ 栏 ├──────────────────────────────┤
│ 72 │ 页面（最大宽度 1080，居中）    │
│ px │                              │
├────┴──────────────────────────────┤
│ 状态栏 24px：诊断 · 目标 · 模型 hash │
└───────────────────────────────────┘
```

- 侧栏：图标 + 文字标签（七项：总览 数据流 状态机 通信 代码 调试 生成）。
- 1366×768 不出现横向滚动；表格自己内部滚动。
- 页面结构：`<h1>` 一句话标题 → 若干 `section.card`。卡片只有 1px 边框，无阴影。

## 组件约定

- **句子行**（`.sentence`）：`序号 动作 目标 ← 来源 参数`，标识符用 `.id` 等宽小标签。
- **徽标**（`.dot`）：8px 圆点 + 文字，颜色取 `--ok/--warn/--err`。
- **诊断**：`at`（等宽、弱色）→ `message`（主）→ `hint`（次）。永不弹模态。
- **按钮**：主按钮（蓝底，一页最多一个）/ 次按钮（描边）/ 文字按钮。所有按钮有文字，可键盘聚焦。
- **图标**：`@phosphor-icons/react`，`size=18`，`weight="regular"`，仅作辅助，不代替文字。

### 总览页

- 第一屏回答"整机怎么跑"：时间线（按 `analyze.plan` 的槽位顺序画泳道，格子位置 = `period_ms`）和概念图。**同一事实只出现一次**，所以原来的"执行计划"文字表已删除，细节留在时间线每条泳道右侧。
- 时间线三条规则：只用 `plan` 的数据算位置，不推断调度；受状态机控制的泳道画闸门并用暖色标记；运行时给"现在"游标，长周期画不下时明确写出"图上只画了前 N ms"。
- 概念图只画真实关系：输入→数据流（读）、数据流→信号（写）、信号→输出（写硬件）、状态机→数据流（启停）、数据流→事件（发事件）。

### 状态机页

- 顶部选择状态机；中部关系图与详情并排（图内“新增状态”）；底部按原始顺序列出“当……时，从……到……”的转换，末尾“新增转换”。
- 详情区顺序：运行的数据流（复选）→ 进入时设置信号 → 钩子函数；头部是就地编辑的状态名 + “设为初始”“删除”。**不要在正文再放一个重复的「名称」框**。
- 「进入时设置信号」只列 `state.set` 里真实存在的键：把全部信号连同初值列出来会让人以为进入状态时都会写一遍。
- 目标正在运行时，当前状态用绿色边框 + “运行中 Ns”标出；没有运行时只有“初始”徽标。模型哈希与快照不一致时不要高亮。
- 状态 label 优先显示，id 次级显示；初始状态用文字标记。蓝色只表示浏览选中，不表示目标正在该状态运行。
- 图的坐标只用于布局。路径数字与规则序号对应；图是句子列表的辅助展示，键盘用户可以通过状态按钮与规则按钮完成同样的查看。
- 空项目、无转换、多状态机、任意来源与自转换都必须可读；超过区域大小的图局部滚动。800px 以下详情放在图下方。

### 通信与代码页

- 通信页用分类按钮和搜索框缩小列表；选择对象后在下方展示关系，避免为每个对象堆叠卡片。名称优先、id 次级；初始值、模型配置与实时数据必须明确区分。
- 内存只展示分析接口提供的类别合计。没有队列关系分析时直接说明，不推测用户 C 代码的生产者和消费者。
- 代码页为文件列表 + 编辑区，只有“保存文件”是主按钮。新文件、函数骨架先进入可编辑草稿，保存成功后更新函数分析。
- 保存失败在编辑区上方显示原因，保留内容。未保存状态用文字表达；页面切换不销毁草稿。Monaco 跟随明暗主题，在本地按需加载。
- 固定结构与用户逻辑区用底色区分：`EFW USER BEGIN/END` 之外的行加 `--bg-inset` 底色，在标记外按键或粘贴时提示“模板结构由工具维护”。标记内不允许再出现保留标记。
- `efw.json` 作为“应用配置”列在源码文件上方，可整体编辑；保存即更新模型，其他页面在保存后按新模型刷新。JSON 语法错误在保存时提示，不写入磁盘。

### 调试页（目标选择）

- 启动卡片用三个 `aria-pressed` 按钮选目标（虚拟目标 / 串口目标 / TCP 目标），选中的那一个显示对应参数；回放单独一块，不混在目标选择里。
- 真机目标是“连接”而不是“启动”：按钮文案分别是“启动虚拟目标”“连接串口”“连接 TCP”。参数没填全时按钮禁用，`title` 说明缺哪一项，不用错误条常驻占位。
- 目标选择是全局状态，顶栏“运行”与本页共用；不要出现两处各选各的。
- 启动失败没有会话可显示，错误必须出现在启动卡片上（`role="alert"`），不能只放在会话卡里。

### 调试页

- 状态行只放事实：目标类型、会话 id、状态点（绿=运行、黄=暂停/停止、红=出错）、仿真时间；控制按钮一行，主操作是播放/暂停，停止放在行尾。
- 曲线用内嵌底色面板（`--bg-inset`），序列色 `--s1`–`--s5` 只用于数据；通道用图例开关切换，图例同时显示当前值。
- 任务、状态机、参数、事件、队列各自一张卡片；异常计数（丢拍/超限/错误/丢包）只在非零时标红，不提前着色。
- 参数整定一行三列：名称（label 与 id）、滑杆、数字框；范围来自后端 manifest，不在前端猜测。
- 目标 id 用于定位与测试（行上带 `data-id`/`data-key`），文案只用于显示。

### 生成页

- 一行摘要 + 两个动作：`重新预览`（次要）与`提交生成`（唯一主按钮）。新增/更新/删除/冲突用 chip 颜色区分，未变化用弱色。
- 左列文件、右侧 Diff，沿用代码页的“列表 + 编辑器”布局；Diff 只读、行内模式、隐藏未改动区域。
- 阻止覆盖（手改生成文件）用诊断条说明原因，不弹模态；提交失败时保留当前预览。

### 总览页的修复入口

“下一步”里每条能定位的诊断都是真正的 `<button>`（键盘可达，`aria` 与选中态一致），末尾写明去向，例如“去通信页 · 信号 temp_raw”，右侧一个 `›` 暗示可点。无法定位的（如 `project` 级的模型错误）保持纯提示，不假装能跳。点击后切页并**选中出问题的那个对象**：数据流滚到该卡片、状态机选中该状态或转换、通信切到对应分类并选中、代码页打开对应文件。跳转映射在 `ui/focus.ts`，只按后端诊断的 `at` 前缀判断（`flows/`、`machines/`、`signals/`、`comms/<分类>/`），不猜语义。

### 页面内模型编辑（通信、数据流、状态机三页均已实现）

- 编辑动作只改内存模型，统一经 `updateModel`：校验 → `project.save`（带 revision）→ 全页刷新；失败保留原模型、输入框回滚，用诊断条说明。
- 数据流：点开步骤行改字段、上移/下移、增删步骤与数据流；状态机：状态详情与转换规则就地编辑、增删与排序；通信：表格行内编辑与增删（信号/输入/输出/事件/队列）。
- 下拉没有选中值时必须显示“选择…”占位项，否则浏览器会显示第一项，看起来像已经选好了。
- 切换枚举类型（如仿真类型）时预填该类型的默认值，含引用型字段，避免新值非法导致保存被拒、用户无法完成配置。
- 行内输入默认无边框，悬停或聚焦才出现（`.input.cell`），避免表格像表单；下拉与复选框即时提交，文本与数字失焦或回车提交。
- 保存期间输入框保持可用（编辑在 store 内串行排队），只有新增/删除按钮在处理中禁用。
- 数据流页把每条步骤渲染成一行句子，点击展开字段表单；排序用上移/下移按钮（键盘可达），不用拖拽。步骤字段由后端 `step_specs` 驱动，新增/改类型不写死在界面。
- id 由工具生成、不可改；删除前检查引用，有引用时先说明再决定。不引入自由画布与节点连线。
- 可点击元素带 `data-id`/`data-key`；确认删除用行内两步确认（删除 → 确认删除），不用模态。

## 代码组织

```
ui/
  main.tsx          入口
  App.tsx           壳：侧栏/顶栏/状态栏 + 路由（useState，无路由库）
  rpc.ts            与服务通信（唯一入口）
  store.tsx         项目与调试状态；sourcesDirty 由代码页维护
  types.ts          与后端字段一一对应的类型（依据 docs/02、docs/04）
  debug.ts          调试帧 → 界面状态的归约
  template.ts       源码模板标记解析（与后端 source_template.py 同规则）
  monaco.ts         Monaco 初始化与语言注册（编辑器/Diff 共用）
  pages/            每页一个文件；只读 store，写入走 store 的 action
  components/       SourceEditor / CurveChart / DiffView
  styles/           tokens.css（变量）+ app.css（布局与组件）
```

## 通信（浏览器开发与 Electron 同一份代码）

`ui/rpc.ts` 暴露 `call(method, params)` 与 `onEvent(fn)`。开发时由 `tools/bridge.mjs`（Vite 中间件）把
`POST /rpc` 转给 `python -m studio_core.server`，`GET /events` 用 SSE 推送通知；Electron 阶段只需换 rpc.ts 的底层传输。

## 撤销与草稿

- 撤销/重做只针对模型编辑，且走同一条写盘链路（校验 → `project.save`），所以磁盘与界面不会出现"撤销了一半"的状态。历史上限 50 步，重新载入或换项目即清空；新编辑丢弃重做分支。
- 快捷键在焦点位于输入框、下拉或 Monaco 时不拦截，交给控件自己处理。
- 源码草稿是编辑器的文本，靠 Monaco 自带的 `Ctrl+Z`；工具只负责"别丢"：按项目持久化到 localStorage，恢复时明确告诉用户恢复了哪些文件。

## 蓝图与结构图

- 蓝图（数据流页）：位置永远由执行顺序自动算出，不存坐标；**拖动盒子改的是执行顺序**，是真模型变更，要走 `updateModel` 的校验与写盘。
- 连接线上的文字必须是模型里真实存在的字段关系（上一步写出、下一步读入的同一个信号），不画“看起来像”的连线。
- 颜色只表达类别：读（输入）/ 算 / 写（输出）/ 事件。用 `--s1`–`--s5`，不新增颜色。
- 结构图（总览）：六列固定顺序（输入 · 数据流 · 信号 · 输出 · 状态机状态 · 事件）。只画**被用到**的对象；没人读写的信号不出现，图例写明"N/M"。
- 连线走**正交通道**并按目标行号分道（同一对列之间最多三条错开），不要用贝塞尔曲线挤在列缝里；悬停某个盒子时只亮它的边，其余淡出。盒子宽度要放得下"名称 + id"两行文字，宁可横向滚动也不要压缩到看不清。
- 图上每个盒子都能点开：跳到能编辑它的页面并选中对象（复用修复入口），这样图不是死图。

## 名称与标识符

- 新建任何对象都是两个框：**名称**（中文，只影响显示）和**标识符**（英文小写，进入生成的 C 代码，创建后不可改）。
- 必须用 `NameIdFields` 组件，并给出按种类推导的真实 C 名字预览；不要让用户猜“下面那个框是什么”。
- 表格里的两列表头也要标注“只影响显示 / 进入 C 代码，不可改”。

## 概念说明必须写在界面上

- 新手最常混的三件事：**信号 vs 常量**、**信号 vs 事件**、**输入/输出对应哪个 C 函数**。这些不能只写在文档里。
- 通信页每个分类上方一行说明，用 `**强调**` 与反引号 `代码` 两种记号就地渲染，不塞 HTML。
- 步骤字段的语义来自后端 `step_specs[].hint`（信号字段 / 常量参数 / 事件比较各不相同），界面不自行编解释。
- `label` 是无障碍名，必须稳定；解释性文字放 `hint`，改动 label 会破坏测试与读屏定位。
- 等待后端往返的界面不能留空白：欢迎页模板未到时显示骨架，取不到时说明原因。

## 外壳（IDE 化）

- 左侧是可折叠的资源树（`Ctrl+B`）：视图 / 项目文件 / 模型对象 / 诊断。树里任何条目都可点，跳到能编辑它的页面并选中对象——树是导航，不是只读清单。
- 分组标题用 `事件（1）` 这种全角括号写法，**不要**和通信页的分类按钮（`事件 1`）重名，否则无障碍名撞车、测试选择器歧义。
- 命令面板 `Ctrl/⌘+K`（`Ctrl/⌘+P` 同义）：输入即过滤，`↑↓` 选择、`Enter` 执行、`Esc` 关闭；焦点在输入框时快捷键不与页面抢。
- 代码页仍保留自己的文件列表：侧栏收起时没有别的入口。两处都在无障碍树上属于不同地标（`navigation` 与 `complementary`），测试要指明是哪一处。
